# Mobile bills and checkout (#109)

The Hóa đơn tab separates active desktop sessions and paid invoices. Search is performed on the desktop before pagination by customer name/phone or bill ID; paid invoices can be filtered by salon payment date. Each section keeps its query, filter and scroll position on return.

A bill has compact customer/line/total/payment groups and a fixed VND total/action. Products retain negative-stock warnings without preventing sale. Adding items uses the same paginated catalog picker. Editing a line opens a separate screen: quantity and employee are available to staff/cashier/owner, price only to owner. One durable sessionUpdateLine command joins the desktop transaction, so any rejected price/employee update rolls back the entire line edit.

Payment defaults to one method for the full desktop total. Split fields appear on request and require an exact allocation. A locally selected allocation stays on its own bill and requires confirmation before being discarded on refresh/back. Checkout review includes customer, every line/employee, totals, allocation and negative-stock notice. If an allocation needs saving, it is saved first; the resulting desktop snapshot must still match the reviewed bill before checkout proceeds. A concurrent change requires a fresh review. Checkout itself uses the current revision and existing durable commandId journal.

Unknown checkout/payment results block new mutations and retain their exact command on the phone. Check/retry operates on that command; a recovered payment configuration does not automatically checkout. A committed invoice opens the receipt. Receipt loading failure offers re-read, never another checkout. Background/revoke still removes the nested workspace and its data dialogs; revoked pending requests remain protected for desktop review.

CI covers roles, atomic rollback/targeting, many bills/search, split allocation, repeated taps, stale revision, uncertain-result recovery, keyboard/large text and stock warnings. Linux CI adds nine billing images to mobile-ui-review using Flutter engine renders with the production theme. These images are technical/visual review evidence, not a real Android phone. Physical salon↔phone QA remains #111; realtime/reconnect remains #110. No local app build/test, deployment, production migration or installation is performed in this batch.
